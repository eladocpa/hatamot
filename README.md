# 🧾 כלי אוטומציה להתאמות בנק — הפקדות שיקים

כלי שעובר על מסך התאמות הבנק במערכת **Invoice Maven**, מאתר את כל
תנועות **"הפקדת שיק"**, קורא את צילומי השיקים בעזרת **Claude**, מתאים כל
שיק ללקוח ברשימה שלך, ובונה **קובץ אקסל** מסודר לבדיקה.

> **שים לב:** בשלב הזה הכלי **לא מוציא קבלות** — הוא רק בונה את הטבלה
> ונותן לך לבדוק. שלב הוצאת הקבלות יתווסף אחרי שתאשר את הטבלה.

---

## 📋 מה צריך להכין מראש (פעם אחת)

1. **Python 3.10 ומעלה** מותקן במחשב — מ-https://www.python.org/downloads/
   (בווינדוס: בהתקנה **סמן** את התיבה "Add Python to PATH").
2. **מפתח API של Claude** — מ-https://console.anthropic.com → API Keys.
   מחרוזת שמתחילה ב-`sk-ant-...`. צריך שיהיה קרדיט בחשבון.
3. **רשימת הלקוחות שלך** בקובץ אקסל (נכין יחד בשלב 3 למטה).

---

## 🚀 התקנה והרצה — צעד אחר צעד

הפקודות מורצות ב**טרמינל** (בווינדוס: "Command Prompt" או "PowerShell";
במאק: "Terminal"). קודם נכנסים לתיקיית הכלי:

```bash
cd hatamot
```

### שלב 1 — התקנת הספריות

מתקין את כל מה שהכלי צריך (פעם אחת):

```bash
pip install -r requirements.txt
```

ואז מתקין את הדפדפן שהכלי מפעיל (פעם אחת):

```bash
playwright install chromium
```

### שלב 2 — הכנסת מפתח ה-API

יוצרים קובץ הגדרות סודי מתוך הדוגמה:

```bash
# בווינדוס:
copy .env.example .env
# במאק / לינוקס:
cp .env.example .env
```

עכשיו פותחים את הקובץ `.env` (בכל עורך טקסט — Notepad מספיק),
ומדביקים את המפתח שלך אחרי הסימן `=`. לדוגמה:

```
ANTHROPIC_API_KEY=sk-ant-api03-abc123...
```

שומרים וסוגרים. **המפתח נשאר רק אצלך** — הוא לא נשמר בקוד ולא עולה ל-git.

### שלב 3 — הכנת רשימת הלקוחות

יוצרים תבנית ריקה:

```bash
python create_customer_template.py
```

נוצר קובץ בשם `customers.xlsx` עם שתי עמודות: **שם** ו**מזהה**.
פותחים אותו באקסל, **מוחקים את שורות הדוגמה**, וממלאים את הלקוחות
האמיתיים שלך — שם הלקוח בעמודה "שם", ומספר הלקוח במערכת בעמודה "מזהה".
שומרים וסוגרים.

> ככל שהשמות נקיים ומדויקים יותר — ההתאמה תהיה טובה יותר.

### שלב 4 — הרצת הכלי

```bash
python main.py
```

מה שיקרה:

1. **ייפתח דפדפן** על מסך הכניסה של Maven.
2. הכלי **יעצור ויחכה לך** — תקליד בדפדפן שם משתמש וסיסמה ותתחבר.
3. אחרי שהתחברת, חזור לטרמינל ו**לחץ Enter**.
4. הכלי ינווט לבד למסך התאמות הבנק, יאתר את כל הפקדות השיקים,
   יוריד את הצילומים, ישלח אותם ל-Claude ויחלץ את הפרטים.
5. בסוף ייווצר קובץ **`תוצאות_שיקים.xlsx`** עם הטבלה המלאה.

## 🎯 שיפורי דיוק (אופציונליים)

הכלי עובד מצוין רק עם שם, אבל אפשר לחזק את הדיוק עם שני דברים:

**1. עמודת ח.פ בקובץ הלקוחות** — הוסף ל-`customers.xlsx` עמודה שלישית בשם
`ח.פ`, ומלא בה את מספר ה-ח.פ של כל לקוח. הכלי יזהה את ה-ח.פ על השיק
ויתאים לפיו — התאמה **ודאית** (100%), גם אם השם משובש בקריאה. בנוסף,
ה-ח.פ מהרשימה יוצג בטבלת התוצאות (עמודה "ח.פ במערכת") ליד ה-ח.פ שזוהה
בשיק, כדי שתוכל להשוות בעין.

**2. קובץ תנועות הכנסה** — צור קובץ בשם **`income.xlsx`** באותה תיקייה,
עם שלוש עמודות: `סכום`, `שם`, ו-`תאריך` (אפשר להריץ
`python create_income_template.py` כדי לקבל תבנית מוכנה). מלא בו את תנועות
ההכנסה. הכלי מצליב:
- **סכום זהה בדיוק** לשיק, **+**
- **שם תואם**, **+**
- **תאריך הכנסה מוקדם** (או שווה) לתאריך פירעון השיק — כי כמעט תמיד
  ההכנסה נרשמת לפני מועד פירעון השיק.

כששלושת התנאים מתקיימים → חיזוק חזק להתאמה (התאמת שם חלשה הופכת ל"מוכן").
עמודת התאריך אופציונלית — בלעדיה ההצלבה תהיה לפי סכום+שם בלבד.
אם הקובץ לא קיים — מדלגים על השלב, הכל עובד.

## ⛔ זיהוי שיקים שחזרו

שיק שחזר מופיע ב-Maven ב**שתי** שורות: שורת **"הפקדת שיק"** (ההפקדה המקורית)
ושורת **"החזרת שיק"** (פעולת ההחזרה, גם עם צילום). הכלי עובד בשני מעברים:

1. **קורא את כל השיקים** — גם הפקדות וגם החזרות — ומחלץ מספר שיק מכל אחד.
2. **מצליב לפי מספר שיק:** כל מספר שיק שהופיע בשורת "החזרת שיק" מסומן כ"חזר",
   ו**ההפקדה התואמת** מסומנת **"שיק שחזר - לא להוציא קבלה"** (אדום) —
   גם אם ההתאמה ללקוח הייתה ודאית. גיבוי לפי סכום אם אין מספר שיק.

ככה לא תוציא קבלה על הפקדה של שיק שבסוף חזר.

## 📊 איך נראית הטבלה שמתקבלת

| עמודה | מה יש בה |
|-------|----------|
| שם לקוח שזוהה | השם שזוהה על השיק |
| לקוח מותאם ברשימה | הלקוח שלך שהותאם |
| רמת ודאות | כמה ההתאמה בטוחה (%) |
| מספר שיק / בנק / סניף / חשבון / תאריך פירעון / סכום | פרטי השיק |
| תאריך הפקדה | תאריך ההפקדה כפי שמופיע בדף הבנק — **זהו תאריך הקבלה** שתוצא |
| סטטוס | "מוכן לקבלה" או "דורש בדיקה ידנית" |

- 🟢 **שורות ירוקות = "מוכן לקבלה"** — התאמה ודאית.
- 🟡 **שורות צהובות = "דורש בדיקה ידנית"** — הכלי לא היה בטוח ולא ניחש.
  כאן אתה מחליט.
- 🔴 **שורות אדומות = "שיק שחזר"** — לא תוצא עליהן קבלה.

## 🧾 הוצאת קבלות (שלב אחרון)

הקבלות מוצאות דרך ה-API הרשמי של Maven (קבלה = doc_type 400, תשלום בשיק).
**לכל לקוח מיוצג יש מפתח API משלו** — הגדר אותו ב-`.env`:
```
MAVEN_API_KEY=המפתח-של-הלקוח-המיוצג-שאתה-מעבד
```

אחרי שבדקת את הטבלה, מוציאים קבלות עם **שלוש רמות בטיחות**:

1. **סימון:** בעמודה **"לאשר?"** (הראשונה), כתוב **"כן"** בשורות שברצונך
   להוציא להן קבלה. שורות "מוכן לקבלה" כבר מסומנות "כן" כברירת מחדל. שמור.

2. **הרצה יבשה** (לא פונה ל-Maven כלל) — לראות מה ייצא:
   ```
   python issue_receipts.py
   ```

3. **מצב בדיקה** (Maven בודק את הבקשה אך **לא** יוצר קבלה — `test=1`):
   ```
   python issue_receipts.py --test
   ```

4. **הוצאה אמיתית** (יוצר קבלות באמת — `test=0`):
   ```
   python issue_receipts.py --real
   ```

**הגנות מובנות:**
- מוציאים קבלה רק לשורות שסומנו "כן".
- **לעולם** לא מוציאים קבלה לשיק שחזר (גם אם סומן "כן" בטעות).
- כל קבלה נרשמת ב-`receipts_log.csv` — אי אפשר להוציא פעמיים לאותה תנועה.
- מספר האסמכתא נשלח כ-`doc_id`, כך ש-Maven עצמו מונע כפילויות.
- ח.פ שזוהה נשלח כ-`identification` של הלקוח.
- **שני תאריכים נפרדים בקבלה:**
  - **תאריך הקבלה** = תאריך המסמך (`document_date`) — נלקח מעמודת
    **"תאריך הפקדה"** (תאריך ההפקדה מדף הבנק). אם חסר, Maven מציב את היום.
  - **תאריך פירעון השיק** (`payment_date` בתוך פרטי השיק) — נלקח מעמודת
    **"תאריך פירעון"**. אם חסר, נופלים חזרה לתאריך ההפקדה.
- **סדר כרונולוגי:** הקבלות מוצאות לפי **תאריך הפקדה בסדר עולה** (מהמוקדם
  למאוחר), כי Maven דורש שתאריכי מסמך מאותו סוג יהיו רציפים. שים לב: לא ניתן
  להוציא קבלה בתאריך מוקדם מקבלה שכבר הוצאה — זה כלל חשבונאי של Maven.
  לבדיקה אם תאריך מסוים יתקבל, הרץ קודם `--test` (Maven מאמת בלי ליצור קבלה).

## 🛠️ אם משהו לא עובד

הקובץ `config.py` הוא לוח הבקרה — אפשר לשנות בו דברים בלי לגעת בשאר הקוד:

- **הכלי לא מוצא את השורות / אייקון המסמך?**
  זה החלק הרגיש (תלוי במבנה האתר של Maven). פתח את `bank_match_scraper.py`,
  בראש הקובץ יש "אזור כיוונון" מסומן. נכוונן אותו יחד מול האתר האמיתי —
  זה נורמלי בהרצה הראשונה.
- **יותר מדי שורות נשלחות לבדיקה ידנית?**
  ב-`config.py`, הורד מעט את `MATCH_CONFIDENCE_THRESHOLD` (למשל מ-88 ל-82).
- **רוצה לחסוך בעלות?**
  ב-`config.py`, החלף את `CLAUDE_MODEL` ל-`"claude-sonnet-4-6"`.
- **עובד עם חברה אחרת ב-Maven?**
  ב-`config.py`, עדכן את `viewCompanyId` בכתובת `BANK_MATCH_URL`.
